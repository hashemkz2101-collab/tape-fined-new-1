# تپه‌یاب (ویندوز) — نسخه‌ی معرفی کادر

در برنامه‌ی ثبت سفارش، کد را **بدون G و B** تایپ می‌کنید. برنامه از روی «کادری که نشانگر در آن است» می‌فهمد
این کد تپه (G) است یا آستین (B)، و در لیست «ستاره جنوب» و «مروارید» جستجو می‌کند.

## نصب
- پایتون ۳.۱۰+ (با tkinter) و برای تشخیص دقیق کادر: `pip install uiautomation`
- اجرا: `python tape_finder.py`  (یا exe از GitHub Actions)

## هر بار که سیستم روشن شد (حدود ۱۰ ثانیه)
برنامه‌ی ثبت سفارش را باز کنید، تپه‌یاب را اجرا کنید (لیست‌ها خودکار می‌آیند)، سپس داخل برنامه‌ی ثبت سفارش:
1. نشانگر را در کادر «کد» بخش تپه بگذارید → **Ctrl+Shift+F1**
2. نشانگر را در **اولین** کادر زیر «کد» بخش آستین بگذارید → **Ctrl+Shift+F2**
3. (اختیاری ولی بهتر) نشانگر را در اولین کادر «کد» بخش شلوار بگذارید → **Ctrl+Shift+F3** (مرز پایین آستین)

معرفی‌ها ذخیره می‌شوند (نسبت به گوشه‌ی پنجره)، پس اگر پنجره سر جایش بماند دیگر لازم نیست تکرار شود.
اگر چیدمان عوض شد یا ردیف آستین اضافه کردید و ردیف‌های پایین‌تر شناسایی نشد، F3 را دوباره بزنید.
ستون آستین «از اولین ردیف تا مرز» حساب می‌شود، پس همه‌ی ردیف‌ها (۱، ۲، ۳، …) جواب می‌دهند.

## اگر جستجو نمی‌کرد (تغییرات این نسخه)
- اگر کادر شناسایی نشود، برنامه **هم تپه و هم آستین** را جستجو می‌کند و زیر نتیجه دلیل شناسایی‌نشدن را می‌نویسد (می‌شود در تنظیمات خاموشش کرد).
- جستجوی دستی: عدد را تایپ کنید و **Ctrl+Shift+F7** (تپه) یا **Ctrl+Shift+F8** (آستین) بزنید؛ نیازی به معرفی کادر ندارد.
- هر خطای داخلی دیگر حلقه‌ی برنامه را متوقف نمی‌کند و در `%APPDATA%\TapeFinder\debug.log` ثبت می‌شود (دکمه‌ی «باز کردن لاگ»).
- کدهای لیست با فرمت‌های `G-012` / `g12` / `G012` هم پیدا می‌شوند.

## عیب‌یابی
- نوار نتیجه عنوان «تپه G12» یا «آستین B5» دارد؛ اگر عنوان اشتباه بود یعنی کادر درست معرفی نشده.
- زیر فرم، «آخرین کادر تشخیص‌داده‌شده» نشان می‌دهد برنامه تایپ شما را چه کادری فرض کرد.
- اگر معرفی نشد (پیام «کادر شناسایی نشد»)، داخل برنامه‌ی سفارش **Ctrl+Shift+F4** بزنید و فایل
  `%APPDATA%\TapeFinder\diagnose.txt` را برایم بفرستید؛ از روی آن روش تشخیص مناسب را اضافه می‌کنم.

## اگر برنامه‌ی سفارش Chromium/Electron باشد (کلاس Chrome_WidgetWin_1 در گزارش)
UI Automation داخل صفحه را نمی‌بیند. برنامه در این حالت از «محل آخرین کلیک» استفاده می‌کند: قبل از F1/F2/F3 داخل کادر کلیک کنید
و موقع کار هم کادر را با ماوس انتخاب کنید (جابه‌جایی با Tab در این حالت شناسایی نمی‌شود).
برای دقت کامل می‌توانید برنامه را با پارامتر `--force-renderer-accessibility` اجرا کنید (به Target میان‌بر اضافه کنید).

## صادقانه
- من روی ویندوز و با برنامه‌ی ثبت سفارش شما اجرا نکرده‌ام. منطق تشخیص کادر (هندسه‌ی نسبی، ردیف‌ها، مرز)،
  بافر کلید و API با تست خودکار (`test_core.py`) تست شده‌اند، ولی خواندن کادر از برنامه‌ی شما بستگی به فناوری آن برنامه
  دارد: اگر UI Automation را پشتیبانی کند عالی است؛ اگر نه، روش جایگزین (مکان نشانگر متن) دقت کمتری دارد.
- گزینه‌ی «آزمایشی: تشخیص از نام گروه‌ها» اگر فرم شما گروه‌هایی با نام «تپه» و «آستین» داشته باشد، بدون معرفی هم کار می‌کند؛ ولی تضمینی نیست.
- هوک کیبورد فقط ارقام تایپ‌شده را نگه می‌دارد. بعضی آنتی‌ویروس‌ها هشدار می‌دهند؛ استثنا تعریف کنید.
